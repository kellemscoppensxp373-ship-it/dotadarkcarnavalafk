## 2. Установка (если запускаете из исходников)

Нужен **Python 3.12+** (при установке обязательно галочка *Add Python to PATH*).

```powershell
cd dotadarkcarnavalafk
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

При первом запуске EasyOCR скачает русскую модель (~100 МБ), это один раз.
Если нет видеокарты NVIDIA — снимите галочку «Использовать видеокарту для EasyOCR».

## 4. Заполнить вкладку «Билеты» — без этого агент не стартует

1. Запустите программу → вкладка **«Билеты»**.
2. В игре откройте панель нужного аркана (например, **СМЕРТЬ**).
3. Посмотрите, кто стоит в **нижней секции** (три значка билета).
4. Впишите имя героя **так, как оно пишется в поиске героев Dota по-русски**
   (например, `Фантом Ассасин`). Если героев несколько — через запятую, агент будет
   их чередовать.
5. В колонке **«Нужно билетов»** поставьте, сколько хотите нафармить
   (`0` = этот аркан не трогать). Агент сам остановится по достижении цели.
6. Нажмите **«Сохранить таблицу билетов»**.

Заполнять все 11 не обязательно — достаточно тех арканов, которые вам нужны.
Внизу видно: «Заполнено арканов: N из 11».

Всё хранится в `data/tickets.json`, его можно править и руками:

```json
{
  "min_yield": 3,
  "arcana": {
    "death": { "name_ru": "СМЕРТЬ", "x3": ["Фантом Ассасин"], "x2": [], "x1": [] }
  }
}
```

> **Почему только ×3?** Игра на «тройном» герое занимает столько же времени, сколько на
> «одиночном», но приносит втрое больше билетов. Параметр «Минимум билетов за игру» на
> вкладке «Управление» стоит на `3` — герои с меньшей отдачей просто игнорируются.
> Опускать его до 2 или 1 имеет смысл, только если для нужного аркана вы не нашли ×3.

## 5. Первый запуск — обязательно в симуляции

Галочка **«Режим симуляции»** включена по умолчанию: агент смотрит, думает и пишет в
журнал, но **мышь и клавиатуру не трогает**.

1. Зайдите в Dota, встаньте в главное меню.
2. Нажмите **«Старт»**.
3. Смотрите журнал. Должны появляться строки вида:
   ```
   состояние: неизвестный экран → главное меню
   клик «Играть» @(1600, 980) (сходство 1.00)
   цикл 1: Фантом Ассасин → 3 бил. аркана «СМЕРТЬ»
   ```
4. Если состояния определяются правильно — выключайте симуляцию и запускайте
   по-настоящему.

**F12 — аварийная остановка в любой момент.** Ещё одна страховка: резкое движение мышью
в левый верхний угол экрана (PyAutoGUI FAILSAFE).

## 7. Необязательно: спрайты героев

Программа работает **без единого PNG** — герой ищется по имени и подтверждается чтением
названия в сетке выбора. Спрайты лишь ускоряют и уточняют:

* `assets/portraits/portrait_*.png` — 3D-портрет из сетки выбора героя;
* `assets/emoji/emoji_*.png` — пиксельная иконка с экрана наград (сверка начисления).

Как нарезать — в `assets/README.md`. Имена файлов берутся из `HERO_DB`
(`scripts/dota_logic.py`).

## 8. Как менять логику без пересборки .exe

Это главная фишка архитектуры — вся логика лежит обычными `.py` рядом с программой.

* **Вкладка «Консоль разработчика»** → выбрать скрипт → «Открыть файл в редакторе» →
  поправить → **«Применить и перезагрузить»**. Изменения вступают в силу мгновенно.
  Код с синтаксической ошибкой не применится, а если модуль упадёт при импорте —
  автоматически откатится на прошлую версию. Кнопка «Откатить» — вручную.
* **Вкладка «Обновление с GitHub»** → указать владельца/репозиторий/ветку →
  **«Скачать с GitHub и применить»**. Я правлю код в репозитории, вы жмёте одну кнопку —
  пересобирать `.exe` не нужно.

## 10. Что исправлено после вашего запуска .exe

Вы прислали три замечания — разбираю каждое.

### 10.1. «Не удалось импортировать vision.py — No module named 'difflib'»

Это была **моя ошибка сборки**, не ваша. Сборщик PyInstaller смотрит только на
`main.py` и его импорты. Файлы из папки `scripts/` подгружаются уже во время
работы, поэтому сборщик про них ничего не знал — и модуль `difflib`, нужный
`vision.py`, просто не попал внутрь .exe.

Теперь список зависимостей вычисляется автоматически: модуль `app/packaging.py`
читает все файлы `scripts/*.py` и передаёт их импорты сборщику. Забыть что-то
вручную больше невозможно, на это есть отдельные тесты.

**Что сделать вам:** скачать новую сборку после того, как GitHub Actions её
соберёт (вкладка Actions → последний зелёный запуск → артефакт
`DarkCarnival-win64`). Старую папку можно удалить, но **сохраните
`data/tickets.json`** — там ваша таблица героев.

### 10.2. Кнопка «Синхронизировать» вешала окно

Загрузка с GitHub шла прямо в потоке интерфейса: пока ждали сеть, Windows
считал окно зависшим. Теперь синхронизация идёт в фоне, а внизу окна появилась
**полоса прогресса** с подписями каждого шага: подключение → скачивание каждого
файла → запись → перезагрузка модулей → готово. Кнопки на время работы
блокируются, окно двигается и закрывается нормально.

Та же полоса показывает загрузку шести скриптов при старте программы.

## 11. Важно: два режима работы

Это ключевое ограничение, о котором нужно знать до того, как вы нажмёте «Старт».

| | **DarkCarnival.exe** | **ЗАПУСК.bat** (из исходников) |
|---|---|---|
| Окно, таблица билетов, планирование | да | да |
| Горячая замена скриптов, обновление с GitHub | да | да |
| **Распознавание текста на экране (OCR)** | **нет** | да |
| **Управление мышью и клавиатурой** | **нет** | да |
| Размер | ~40 МБ | ~2 ГБ после установки |

Почему так: по вашему же требованию `main.py` — тонкая оболочка. Библиотеки
распознавания (EasyOCR + PyTorch) весят около двух гигабайт, и упаковывать их
внутрь .exe нельзя — сборка в GitHub Actions этого просто не переживёт.

**Вывод: для реальной игры запускайте `ЗАПУСК.bat`, а не .exe.**

Файл `ЗАПУСК.bat` лежит рядом с программой и делает всё сам:
1. проверяет, что Python установлен;
2. создаёт виртуальное окружение (один раз);
3. ставит библиотеки из `requirements.txt` (первый раз качает ~2 ГБ, это долго —
   не закрывайте окно);
4. запускает программу.

Просто дважды кликните по нему. Если Python не установлен — скачайте его с
python.org, версию 3.12, и при установке **обязательно** поставьте галочку
«Add python.exe to PATH».

### Проверка окружения

При старте программа теперь сама пишет в журнал, что у неё есть, а чего нет:

```
✓ PySide6 — окно программы
✓ easyocr — чтение русского текста на экране
✗ torch — движок нейросети для EasyOCR
```

Если видите крестики и строку «Вы запустили .exe» — значит, вы в
ограниченном режиме и игра автоматизироваться не будет. Переходите на
`ЗАПУСК.bat`.

## 13. Про кнопку «Синхронизировать» и ошибку 404

Вы увидели шесть строк `HTTP 404`. Причина была не в программе: OTA-клиент
забирает скрипты из ветки **main**, а весь код до этого лежал в рабочей ветке.
В `main` были только README и лицензия — отсюда «файл не найден».

Сейчас код слит в `main`, и кнопка «Синхронизировать» работает. Нажмите её —
в журнале должно появиться «уже актуален» по каждому файлу (значит, ваши
локальные скрипты совпадают с репозиторием) либо «обновлён».

Заодно ошибки GitHub стали человеческими. Вместо кода ответа программа теперь
пишет, что именно не так:

| Было | Стало |
|---|---|
| `HTTP 404` | файл не найден в ветке «main» — проверьте название ветки и папку scripts/ |
| `HTTP 403` | GitHub отказал в доступе — нужен токен для приватного репозитория либо превышен лимит запросов |
| `HTTP 500` | сбой на стороне GitHub, попробуйте позже |
| `network error` | нет связи — проверьте интернет и не блокирует ли антивирус |

**Если решите вести разработку в другой ветке**, впишите её имя на вкладке
«Обновление с GitHub» в поле ветки и нажмите «Сохранить настройки» — клиент
начнёт тянуть файлы оттуда.
